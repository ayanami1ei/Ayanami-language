# 显式生命周期（A4，注解式 `follow_with`）

> 状态：**A4a + A4b-1/2 + A4c（跨函数传播）已实现**（2026-10）。关联：`docs/annotations.md` §7、`docs/knowledge-graph.md`。
> 决策：不使用 Rust 风格 `'a` 类型语法；生命周期关系用 `#[follow_with(...)]` 注解表达。

## 1. 目标与直觉

- 引用必须始终短于被引用对象（不能悬空）。
- 多个来源同时约束时，**生命周期取最短**：任何一个来源失效，引用都算悬空。
- 注解的职责只有一个：**说明某函数/结构体内的引用不会超过（outlive）被引用的对象**。
  函数与结构体字段照常写，类型里不出现生命周期标记。

## 2. 语法

```ayanami
// 函数：返回引用跟随参数 s（返回的 ref 不会比 s 活得更久）
#[follow_with(s)]
fn pick(ref S s) -> ref S { return s }

// 多引用来源：取最短（结果同时被 a、b 绑住）
#[follow_with(a, b)]
fn first(ref S a, ref T b) -> ref S { return a }

// 结构体字段：字段引用的目标必须覆盖实例作用域（实例不晚于被引用对象失效）
struct Holder {
    #[follow_with(owner)]
    ref S item
}
```

- 来源写法：**参数名**（最精确）或**类型名**（唯一匹配时作简写；同名多参数时报歧义，要求用参数名）。
- 字段上的来源：`owner`（包含它的结构体实例，表示“引用 ≥ 实例存活期”）或外部对象名/类型名。
- 现有「单引用参数返回自动省略」保留；只有多引用来源或字段存引用时才需要 `#[follow_with]`。

## 3. 语义（契约 + 检查）

注解是**被编译器验证的契约**，不是新的类型：

1. **函数**：返回类型中的每个引用必须“派生自”列出的来源之一
   （数据流：直接返回参数、经局部/字段透传、或调用其他带 `follow_with` 的函数）；
   借用检查器把返回 loan 绑定到来源参数的 loan，调用点据此校验实参寿命。
2. **字段**：构造 `Holder` 时，字段引用的 loan 必须覆盖 `Holder` 实例的整个作用域；
   即实例不能晚于被引用对象失效。
3. **最短规则**：多来源时，返回/字段引用的有效期 = 所有来源 loan 的交集（最短者）。
4. **失败诊断**：给出具体位置与来源名（“返回的引用来自参数 `b`，但 `follow_with` 只声明了 `a`”；
   “字段引用的目标可能早于 `Holder` 失效”）。
5. 未注解时：单 `ref` 参数沿用省略规则；多 `ref` 参数且返回引用 → 报错要求补 `#[follow_with]`。

## 4. 与现有借用检查（NLL）的关系

- 现有：`mir/borrow/`（CFG + liveness + loan 活性），引用可存局部、最后使用后失效；
  限制：不可存字段/数组、返回仅支持单引用参数省略。
- A4 扩展：
  1. **loan 来源标记**：从参数 `p` 派生的 loan 打上来源 `p`；
  2. **返回检查**：函数出口处，返回的引用必须携带 `follow_with` 声明的来源标记；
  3. **字段存引用**：允许 `struct` 字段类型为 `ref T`；构造点检查字段 loan 覆盖实例作用域；
  4. **跨函数**：调用带 `follow_with` 的函数时，结果 loan 绑定到对应实参的 loan。

## 5. 阶段与验收

- **A4a 语法与校验（已完成，2026-10）**
  - `#[follow_with(...)]` 加入白名单；仅允许函数与结构体字段（枚举/接口/impl 报错）；
  - 字段级属性文法/AST/formatter 保真（`Field = AttrList? Type Ident`）；
  - 至少一个来源、来源必须为标识符；`example/test_follow_with.aya` check/build/fmt 通过。
- **A4b-1 返回检查（已完成，2026-10）**
  - `HirFn/MirFn.follow_sources`；`borrow/follow.rs::match_source`（参数名优先、类型名唯一匹配、歧义报错）；
  - 返回引用必须跟随声明来源之一（多来源=取最短语义）；未注解的多 ref 返回报错并提示补 `#[follow_with]`；
  - 负例：返回来自未声明来源、同名类型歧义、多 ref 未注解，均带诊断。
- **A4b-2 字段存引用（v1 已完成，2026-10）**
  - 允许 `ref T` 字段与非引用字段的引用赋值限制拆分（非引用字段仍拒绝）；
  - 构造点：结构体字面量的引用字段以**实例局部为键登记 loan**（来源必须直接来自引用参数/局部）；
    实例存活期间，被引用变量不可写/移动（沿用 NLL 活性）；
  - v1 保守：含引用字段的结构体**不可整体移动/返回**；来自调用的引用不可存字段；
  - 待后续：逃逸分析（允许返回含引用字段的结构体并做 follow_with 检查）。
- **A4c 跨函数传播（v1 已完成，2026-10）**
  - `borrow/follow.rs::build_table`：FnId → 来源解析（来源名 → 形参位置）；
  - 调用点：被调函数有 `follow_with` 时按声明来源选择实参（取代“第一个 ref 实参”启发式）；
    多来源 v1 取第一个声明来源（最短语义留后续）；
  - 借用收集改为按源码顺序遍历（cfg 逆序构建）；
  - 待后续：多来源联合约束、`defs`/IDE 来源关系展示。

## 6. 影响面与风险

- 涉及：`ayanami.grammar`、`parser`（字段属性）、`parser/ast`、`formatter`、
  `hir/attrs*`（校验）、`mir/borrow/`（来源标记与字段检查）、`lir`（字段引用布局）。
- 风险：字段存引用的内存布局与 drop（现有「引用不可存字段」是简化假设，需同步改
  `mir/lower` 的字段存储检查与 `lir/emit` 的引用字段读写）；
  与现有单引用省略规则的兼容（先保留，逐步收紧）。
